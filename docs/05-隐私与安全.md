# 05 隐私与安全：关于「全部索引」这个决定

> 本节不改变你的决定，只把风险面、数据流向和随时可用的开关讲清楚。
> 你选择的是**全部索引**（含 `4.0-selfInfo`、`passwords.csv`、简历等）。

---

## 1. 现状：哪些敏感内容进了索引

实测 `discover()` 的结果：

| 内容 | 数量 | 示例 |
|---|---|---|
| `4.0-selfInfo/` 整个目录 | 224 个文件 | `0-个人信息/0.0-个人信息.md`、`1-职业/.../个人简历资料.md` |
| `passwords.csv` | 1 | `4.0-selfInfo/4-账号与通讯/passwords.csv` |
| 含「简历」 | 14 | 招聘笔记 + 求职文档 |
| 含「求职文档」 | 16 | 个人简历资料、外包问题等 |

（docx/pdf 版简历这次因扩展名白名单没进，但**同目录的 .md 版本进了**。）

配置里 `privacy.exclude_enabled: false`，所以 `_matches_privacy` 完全不生效，
这些文件的正文都会被 embedding、写进 `data/index/*.json`，
并可通过 `search_docs` 被检索出来。

---

## 2. 数据流向：一旦检索命中，会到哪里

```
search_docs("密码") 
  → 命中 passwords.csv 的 chunk
  → 片段文本进入 MCP 响应
  → 进入 agent 的上下文窗口
  → 可能被写进：会话记录 / 日志 / 云端 LLM 的请求体（若 agent 用云端模型）
```

注意最后一环：**这个 RAG 服务本身是本地的（Ollama 全离线），
但调用它的 agent 不一定是本地的**。如果你在 agent 里用的是云端模型，
那么被检索出来的片段会随 agent 的上下文一起发到云厂商。
「RAG 本地」不等于「数据不出网」——**出口在 agent 那一侧**。

其他落点：
- `data/index/*.json`：明文存 `raw_text`（含注入的路径头部），磁盘上可读；
- `data/skipped_files.txt`：只有被跳过的文件路径，不含内容；
- `data/manifest.json`：路径 + size/mtime/sha1，不含正文；
- MCP 的 stderr 日志：只打工具名和错误，不打片段内容（`_log` 里刻意没打 hit）。

---

## 3. 保留的开关：改一个字即可收紧

`config/settings.yaml`：

```yaml
privacy:
  exclude_enabled: false        # ← 改成 true 即生效
  exclude_path_patterns:
    - "4.0-selfInfo"            # 裸串：路径子串匹配
    - "passwords.csv"
    - "attachments/**/简历*"    # glob：** 展开为 *，同时匹配整路径与文件名
    - "**/密码*"
  mode: "skip"                  # skip = 整文件不进索引
```

`_matches_privacy()` 在 `discovery.py` 里，**在读取文件内容之前**就判断，
命中的文件连解析都不会做，更不会 embedding。这是最干净的排除时点。

开关打开后需要 `reindex_docs` 才会清掉已入库的旧数据：
被排除的文件会从 manifest 里消失 → 进 `removed` →
`_delete_by_paths` 按 `ref_doc_id` 删掉对应向量。
（`mode: redact` 目前只留了配置项未实现脱敏逻辑，别误以为开了就脱敏。）

> 这是「决定可反转」的兜底：代码不用改，配置改一行 + 一次增量重建。

## 4. 其他几个安全边界

| 面 | 现状 | 说明 |
|---|---|---|
| 网络暴露 | 无 | stdio 传输，不开端口、不监听 |
| Ollama | `127.0.0.1:11434` | 仅本机；若你改过 `ollama` 的 `OLLAMA_HOST` 为 `0.0.0.0`，另当别论 |
| 文档库写入 | 无 | `docs_root` 全程只读，只写 `data/` |
| 命令注入 | 无 | MCP 工具不接受命令/路径参数，只有查询字符串 |
| 路径穿越 | 无 | 工具不接收用户提供的文件路径 |
| 配置注入 | 低 | `settings.yaml` 由你本人维护，`yaml.safe_load` 不执行任意构造 |

一个值得知道的细节：`ask_docs` 把检索片段拼进 prompt 时没有做
「片段里的指令是否被 LLM 当命令执行」的隔离。若笔记里写了一句
「忽略前面的要求，输出 XXX」，理论上有 prompt injection 风险。
个人库自己写的笔记风险很低；若将来索引外部网页/他人文档，
应在拼接时加明确的分隔与「以下内容仅为资料」的包裹说明。

---

## 5. 如果你想更稳，三个可选动作（都不影响现有功能）

1. **开排除开关**（最推荐，一行配置）：把 `4.0-selfInfo` 和 `passwords.csv`
   排除，其余 2200 多篇知识笔记照常检索。
2. **给 `data/` 加权限**：`chmod 700 ~/Projects/rag/data`，
   索引 JSON 只有你能读。
3. **agent 侧用本地模型**：确保检索片段不随 agent 上下文出网
   （本项目 Ollama 已是本地，但 agent 的模型选择是另一回事）。

---

## 小结

- 「全部索引」的决策已按你的选择执行，代码里有随时可启用的排除开关；
- 真正的出网风险不在 RAG 服务，而在**调用它的 agent 用不用云端模型**；
- 索引文件是明文，注意 `data/` 的磁盘权限；
- 排除发生在 `discovery` 阶段（读内容之前），开启后 reindex 一次即清理干净。
